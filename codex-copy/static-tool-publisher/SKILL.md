# 独立工具网页与导航发布

默认复用用户现有仓库和 Vercel 项目，以最少文件完成可直接使用的静态工具。导航页只负责跳转，转换、解析、下载等功能必须放在独立页面。

## 工作流

1. 检查现有仓库结构、导航源码、构建命令、输出目录和生产域名，优先沿用现有 HTML/CSS/JS 风格。
2. 先判断浏览器端原生能力是否足够。能用静态 HTML、原生 JavaScript、Web API 或已经存在的依赖完成时，不增加框架和后端。
3. 每个工具创建独立页面；导航首页只新增名称、说明和链接，不在首页嵌入工具表单或处理逻辑。
4. 批量任务提供多文件选择、逐项状态、单项失败隔离和可重复下载；用户要求“一点就解析并下载”时合并多余步骤。
5. 外部链接解析只处理公开可访问内容，尊重目标站点登录、签名、防盗链和跨域限制；不能稳定前端完成时，用最小同源 API 解决，不伪装成纯前端成功。
6. 构建必须把新增的每个 HTML、脚本和资源复制到实际发布目录。提交文件存在并不等于生产 URL 可访问。
7. 通过 GitHub 仓库提交发布，保持导航项目和其他已有部署互不覆盖。

## Vercel 与仓库约束

- 单仓库多页面项目应明确 Root Directory、构建命令和 output directory，避免 Vercel 执行仓库根目录的无关构建。
- 静态项目优先使用简单复制构建，例如将所需页面复制到 `dist`；只有真实需求才引入打包器。
- 更新已有项目时优先修改原项目，避免创建重复 Vercel 项目或重复导航入口。
- Git 更新使用非强制提交；保留用户现有文件和历史。

## 完成验证

发布后逐个检查：

- 导航首页返回成功且新增入口可见。
- 每个独立工具的精确生产 URL 返回成功，不是 404 或旧缓存页面。
- 页面核心流程在生产域名实际运行，至少验证一个成功样例和一个错误提示。
- 导航链接指向生产页面，工具页不依赖本地路径。

只有源码、构建产物、仓库提交和生产 URL 都验证后，才报告“已发布”。
